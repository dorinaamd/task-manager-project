
# Test Strategy – Daybreak Tasks

## 1. Objective

The purpose of this testing strategy is to evaluate the functionality, reliability, and usability of the Daybreak Tasks application.

The testing process aims to identify defects and verify that the application meets its requirements.

## 2. Scope

Testing will focus on the following features:

- Creating tasks with different importance levels
- Editing task information
- Deleting existing tasks
- Marking tasks as completed or incomplete
- Filtering tasks by category
- Validating task titles and descriptions
- Checking the user interface

## 3. Testing Types

- Functional Testing
- User Interface Testing
- Negative Testing
- Regression Testing
- Exploratory Testing

## 4. Testing Approach

Manual black-box testing will be performed to verify the main features of the application.

Test cases will be executed using different input values and user actions.

Expected results will be compared with actual results.

Any identified defects will be documented with reproduction steps, severity, and supporting evidence.

## 5. Test Environment

- Operating System: Windows
- Browser: Google Chrome
- Application: Daybreak Tasks
- Development Environment: Visual Studio Code
- Version Control: Git and GitHub
- Runtime Environment: Node.js
- Testing Method: Manual Testing

## 6. Risks

Potential risks during testing include:

- Incorrect task information updates
- Loss of task descriptions
- Invalid task creation
- Incorrect task completion status
- Problems with category filtering
- User interface inconsistencies

## 7. Exit Criteria

Testing will be considered complete when:

- All planned test cases have been executed.
- Test results have been documented.
- Identified defects have been reported.
- At least two bugs have been investigated.
- One bug has been traced to the relevant source code.
