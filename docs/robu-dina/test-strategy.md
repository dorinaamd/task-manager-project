# Test Strategy – Daybreak Tasks
## 1. Objective

The objective is to evaluate the quality, functionality, and usability of the Daybreak Tasks application.

## 2. Scope

Testing will cover the main features of the Daybreak Tasks application:
- Creating tasks
- Editing tasks
- Deleting tasks
- Marking tasks as completed
- Input validation
- User interface functionality

## 3. Testing Types

- Functional Testing
- User Interface Testing
- Negative Testing
- Regression Testing

## 4. Testing Approach

Manual black-box testing will be used to verify the application functionality.

Each test will compare the expected result with the actual result.

Any discovered defects will be documented in bug reports.

## 5. Test Environment

- Operating System: Windows
- Browser: Google Chrome
- Application: Daybreak Tasks
- Development Environment: Visual Studio Code
- Version Control: Git and GitHub
- Testing Method: Manual Testing

## 6. Risks

Potential risks during testing include:

- Incorrect task creation
- Data loss
- Application crashes
- Incorrect task status updates
- User interface errors

## 7. Exit Criteria

Testing will be considered complete when:

- All planned test cases have been executed.
- Identified bugs have been documented.
- Critical defects have been reviewed.
- Test results have been recorded.
