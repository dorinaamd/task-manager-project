Bug 01 
Можно создать задачу с пустым названием или из одних пробелов. Если оставить поле «What do you need to do?» пустым (или ввести туда пару пробелов) и нажать кнопку «Create Task», задача всё равно создаётся без названия — появляется пустая карточка только с важностью, категорией и кнопками. По первому пункту требований Title является обязательным полем, поэтому сайт должен блокировать создание такой задачи и выводить ошибку.

Bug02
Название задачи может оставаться с маленькой буквы в двух случаях: если при создании внутри текста уже есть другая заглавная буква (например, «vova Lisovoy» так и создаётся с маленькой буквы, хотя обычное «buy milk» исправляется на «Buy milk»), а также при редактировании через кнопку «Edit», где любое слово с маленькой буквы сохраняется без исправления. По шестому пункту требований название должно начинаться с заглавной буквы в любом случае.

Bug03
При редактировании задачи можно полностью удалить её название и сохранить пустую карточку. Если нажать кнопку «Edit», стереть текст из поля названия (или оставить там только пробелы) и сохранить изменения, задача остаётся без заголовка. По первому пункту требований Title является обязательным полем, поэтому система должна запрещать сохранение задачи с пустым названием.

Bug04
Невозможно создать задачу без категории, хотя по требованиям это поле необязательное. В выпадающем списке «Category» есть только четыре варианта (Work, Social, Home, Hobby) и по умолчанию сразу выбрано «Work». Пункта «Без категории» или пустого значения в списке нет, поэтому пользователь не может оставить это поле пустым. По второму пункту требований Category является необязательным полем, значит в списке должен быть вариант создания задачи без категории.

Bug05
Неправильно работает сортировка задач по приоритету. Если создать три задачи с разной важностью (High, Medium, Low) и выбрать в фильтре «Priority: High to Low», карточки выстраиваются в неверном порядке: сначала идёт Medium, затем Low и только в конце High. Ожидается, что при выборе сортировки от высокого приоритета к низкому первой будет отображаться задача с важностью High, затем Medium и последней Low.

Bug06
Баг с возвращением удалённой задачи:
Удаление задачи не сохраняется после перезагрузки страницы. Если нажать красную кнопку «Delete», карточка пропадает с экрана, но стоит обновить страницу (F5), как удалённая задача снова появляется в списке. Удаление должно сохраняться, чтобы после перезагрузки удалённые задачи не возвращались.

Недочёт с удалением без подтверждения (UX):
Задача удаляется в один клик без какого-либо предупреждения. При нажатии на кнопку «Delete» карточка исчезает моментально, из-за чего можно случайно удалить важную задачу. Для удобства и безопасности пользователя перед удалением должно появляться окно с подтверждением (например, «Вы уверены, что хотите удалить задачу?»).

Bug07
Ломается вёрстка карточки, если ввести длинный текст без пробелов в название или описание. Если создать задачу с длинным словом подряд (например, 80–100 символов без пробелов), текст не переносится на новую строку и не обрезается, а вылезает далеко за границы своей карточки, наезжает на соседнюю карточку справа и уходит за край экрана. Длинный текст должен автоматически переноситься по словам или символам внутри карточки, чтобы не ломать интерфейс.

Bug08
Изменения, сделанные с задачами, не сохраняются после перезагрузки страницы. Если отредактировать задачу через кнопку «Edit», удалить её через «Delete» или создать новую, а затем обновить страницу в браузере (F5), все изменения пропадают: удалённые задачи возвращаются, а отредактированные откатываются к исходному виду. Приложение должно сохранять текущее состояние списка задач (например, в хранилище браузера или базе данных), чтобы данные не терялись при обновлении страницы.
